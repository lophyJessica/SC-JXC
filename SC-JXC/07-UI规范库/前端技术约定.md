# 前端技术约定（原型工程）

> 适用范围：`99-产品原型/前端工程/` 里的可点击原型。页面长什么样看同目录的《页面风格约定》；本文件只管"代码怎么写、放在哪"。
> 原型是给业务方看的演示品，不是正式系统：**只有前端，没有后端和服务器，数据全是演示数据，存在浏览器自己的本地数据库里。**

## 一、技术栈（不要换，不要加）

| 用途 | 选型 | 说明 |
| --- | --- | --- |
| 页面框架 | Vue 3（`<script setup>` 写法） | |
| 组件库 | Element Plus，中文语言包 | 后台风格直接用它，不自己画按钮、表格、弹窗 |
| 路由 | Vue Router，**hash 模式** | 地址里带 `#`，打包后双击打开也能跳转 |
| 全局状态 | Pinia | 只放"演示身份、显示角标"这类全局演示状态 |
| 演示数据 | IndexedDB + Dexie.js | 浏览器本地数据库；刷新后数据还在；可一键重置 |
| 构建 | Vite + vite-plugin-singlefile | 打包成一个 `dist/index.html`，相对路径，双击能开 |
| 运行环境 | Node.js LTS（20.19 及以上，或 22.12 及以上） | 只有开发和打包需要；看 dist 不需要 |

依赖已经写在 `package.json` 和 `package-lock.json` 里。**不新增任何依赖**；确实需要，先列为【待确认】问人。

## 二、怎么运行

在 `99-产品原型/前端工程/` 目录下：

| 场景 | 命令 | 结果 |
| --- | --- | --- |
| 第一次用 | `npm install` | 装好依赖（生成 node_modules，需要联网一次） |
| 边改边看 | `npm run dev` | 自动打开浏览器 `http://localhost:5173`，改代码页面自动刷新 |
| 打包 | `npm run build` | 生成 `dist/index.html`，一个文件，双击就能打开 |
| 看打包结果 | 双击 `dist/index.html` | 不需要 Node，也不需要联网 |

## 三、目录规则

```
前端工程/
├── package.json / package-lock.json / vite.config.js / index.html
├── dist/                      打包产物（npm run build 生成，可以删了重打）
└── src/
    ├── main.js                程序入口：打开演示数据库 → 挂载页面
    ├── App.vue
    ├── router/index.js        路由总表：自动收集 views/**/routes.js
    ├── layout/AdminLayout.vue 后台布局：顶部（演示身份、显示角标、重置演示数据）+ 左侧菜单
    ├── stores/demo.js         演示状态：当前身份、显示角标、员工名单
    ├── config/
    │   ├── menu.js            左侧菜单（模块、单据名称）
    │   └── status.js          状态标签颜色（来自《页面风格约定》）
    ├── components/            公共组件（见第四节），所有单据共用
    ├── directives/anno.js     v-anno 角标指令
    ├── styles/global.css      全局样式
    ├── utils/format.js        金额、日期、单号等小工具
    ├── mock/                  演示数据层（见第六节）
    │   ├── db.js              打开数据库、写种子、重置（只给 repos 用）
    │   ├── seed/<单据>.js     种子数据，来自该单据的"演示数据.md"
    │   └── repos/<单据>.js    数据仓库：页面读写数据的唯一入口
    └── views/
        ├── 公共/              首页、"原型还没做"页
        └── <模块>/<单据>/     每个单据一个文件夹，例如 views/采购/采购订单/
            ├── routes.js      本单据的路由（自动被收集）
            ├── anno.js        本单据的角标编号和文字
            ├── rules.js       本单据的业务规则（只抄主PRD）
            ├── service.js     本单据的动作（提交、审核……），调用 repos
            ├── 列表页/index.vue
            ├── 新增编辑页/index.vue
            └── 详情页/index.vue
```

- 模块文件夹用中文短名：基础资料、采购、销售、库存
- 单据文件夹用单据中文名（与 `01-全局背景信息/04-单据目录与通用状态.md` 一致）；页面文件夹固定叫"列表页 / 新增编辑页 / 详情页"
- 路由地址用英文：`/<模块英文>/<单号前缀小写>`，例如采购订单 `/purchase/cgdd`、`/purchase/cgdd/new`、`/purchase/cgdd/<单号>`、`/purchase/cgdd/<单号>/edit`
- 代码注释写中文；变量名可以用中文（现有代码就是这样），也可以用英文，同一个文件保持一致

## 四、公共组件（能复用就复用，不要自己再造一个）

| 组件 | 用在哪 | 用法要点 |
| --- | --- | --- |
| `QueryBar` 查询区 | 列表页表格上方 | 字段用 `<el-form-item label="…">` 放进插槽；监听 `@search`、`@reset`；`:error` 显示"结束日期不能早于开始日期"这类提示 |
| `StatusTag` 状态标签 | 列表、详情里的状态 | `<StatusTag :status="row.status" />`，颜色自动取 `config/status.js` |
| `ReasonDialog` 原因弹窗 | 驳回、作废、关闭等必须填原因的操作 | `const 原因 = await 弹窗.value.打开({ 标题, 说明, 危险 })`，取消返回 null；自带"请填写原因""原因最多 200 字"校验 |
| `FooterBar` 底部固定按钮栏 | 新增编辑页 | 按钮放进插槽，顺序：取消、保存草稿、提交审核 |
| `v-anno` 角标指令 + `AnnoBadge` | 所有编了角标的区域 | `<div v-anno="角标.L1">`；角标对象来自本单据 `anno.js`；顶部"显示角标"打开才显示 |

其他界面元素（按钮、输入框、下拉、日期、表格、分页、确认框、消息提示）一律用 Element Plus 自带的：确认用 `ElMessageBox.confirm`，提示用 `ElMessage`。

新加公共组件的条件：两个以上单据会用到，并且《页面风格约定》里有对应的规定。

## 五、新增一个单据页面（步骤）

以"销售订单"为例：

1. **先确认上游齐全**：`03-产品设计/<模块>/<单据>/` 下有字段清单详细稿、主PRD、三份 Demo PRD、演示数据.md。缺了就停下汇报
2. **种子数据**：新建 `src/mock/seed/销售订单.js`，把演示数据.md 里的数据原样抄进来，文件末尾导出
   `export const 表们 = [{ 名称: 'salesOrders', 主键: 'no, status', 数据: 销售订单 }]`
   （`db.js` 会自动收集，不用改它；文件开头注释写清"代码字段 ↔ 字段清单里的字段名称"对照）
3. **数据仓库**：新建 `src/mock/repos/销售订单.js`，参照现有仓库写 `查全部 / 按单号取 / 保存 / 删除` 等函数，只做存取，不写业务规则
4. **单据文件夹**：新建 `src/views/销售/销售订单/`，依次写：
   - `anno.js`：角标编号和文字，和 Demo PRD 的角标表一致
   - `rules.js`：状态列表、权限判断（状态—动作矩阵）、金额计算、校验，**只抄主PRD 和 Demo PRD**
   - `service.js`：每个动作"取最新数据 → 用 rules 判断 → 写回"，状态不对时抛出主PRD 里写的提示文案
   - `列表页/index.vue`、`新增编辑页/index.vue`、`详情页/index.vue`
   - `routes.js`：列表页的 meta 写 `{ 菜单: '销售订单', 入口: true }`，其他页写 `{ 菜单: '销售订单' }`
5. **菜单**：`config/menu.js` 里已经有"销售订单"，路由一加，左侧菜单自动变成可点；新单据不在菜单里才需要加一行
6. **自查**：`npm run dev` 点一遍三页；`npm run build` 后双击 `dist/index.html` 再点一遍；控制台没有报错

页面骨架参考（列表页）：

```vue
<script setup>
import { ref, onMounted } from 'vue'
import QueryBar from '@/components/QueryBar.vue'
import StatusTag from '@/components/StatusTag.vue'
import { useDemoStore } from '@/stores/demo'
import { 角标 } from '../anno'
import { 能否 } from '../rules'
import * as 服务 from '../service'

const store = useDemoStore()           // store.me = 当前演示身份 { name, role }
const 列表 = ref([])
onMounted(async () => (列表.value = await 服务.查全部()))
</script>

<template>
  <QueryBar v-anno="角标.L2" @search="…" @reset="…">
    <el-form-item label="销售订单号"><el-input v-model="…" /></el-form-item>
  </QueryBar>
  <el-card shadow="never">
    <el-button v-if="能否('create', null, store.me)" type="primary">新建销售订单</el-button>
    <el-table :data="列表">
      <el-table-column label="订单状态"><template #default="{ row }"><StatusTag :status="row.status" /></template></el-table-column>
    </el-table>
  </el-card>
</template>
```

## 六、演示数据规则（mock 层）

1. **只有前端**：不写后端、不起服务器、不调任何网络接口；数据全部存在浏览器的 IndexedDB 里（库名 `sc-jxc-demo`；双击打开时库名后面会加上文件位置编号，所以不同文件夹里的原型数据互不干扰）
2. **页面不直接碰数据库**：`views/` 里禁止 `import Dexie` 或 `import … from '@/mock/db'`；只能 import `@/mock/repos/…`
3. **种子数据只来自演示数据.md**：一条不少、不另编；改演示数据先改 md，再同步 `mock/seed/`
4. **第一次打开自动写入种子**；刷新后数据还在；种子数据或表结构一改，浏览器里的旧数据自动作废并重新写入
5. **顶部"重置演示数据"**：清空并重新写入种子数据，然后整页刷新。演示前、验收测试前都先点一次
6. **备用**：浏览器不让用 IndexedDB 时自动改用内存存储，顶部出现"内存模式"标记，刷新就恢复初始数据
7. 单号用 `utils/format.js` 的 `nextNo(前缀, 已用单号)` 生成，格式 `前缀-年月日-4位流水`

## 七、原型不能做的事（红线）

1. **字段只能来自字段清单详细稿**：页面上的字段名、列名、查询条件，和详细稿的"字段名称"一字不差；详细稿没有的字段不加
2. **规则只能来自主PRD**：按钮、状态、谁能做什么、校验、提示文案，主PRD 和 Demo PRD 没写的一律不加；文档有矛盾写【待确认】
3. **不发明第二套状态**，状态颜色只用 `config/status.js` 里的
4. 不做登录、不连后端、不调外部接口、不引用外部网络资源（字体、图片、CDN 都不行）
5. 不新增依赖、不升级依赖版本、不改 `vite.config.js` 的打包方式（相对路径 + 单文件 + hash 路由是"双击能开"的前提）
6. 不改公共组件的对外用法；要改先说明影响哪些单据
7. 编了角标的区域必须加 `v-anno`，角标编号和 Demo PRD 一致
8. `node_modules/` 不提交、不拷贝；`dist/` 可以随时重新打包

## 八、验收口径

- `npm run build` 不报错，`dist/index.html` 双击能打开，三页能跳转，控制台没有报错
- 演示身份切换后，按钮按主PRD 状态—动作矩阵显示
- 刷新后数据还在；点"重置演示数据"后恢复初始
- 页面上的字段名都能在字段清单详细稿里找到；角标齐全
