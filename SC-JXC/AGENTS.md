# AGENTS.md（AI 入职手册）

> 指挥官进入本项目，先读完这一页再干活；本地 agent 在指令要求时读它。这里只写"每次都要遵守"的规矩；业务事实不写在这里，去 `01-全局背景信息` 和 `02-需求调研` 找。
>
> 本项目有两类读者：**给人看的**（产品、评审人、开发——看各目录 `说明.md`、`README.md`、中文文档和结构图）和**给 agent 看的**。本手册**主要给指挥官看**：由个人助手型 agent（如 Grok Bot、Hermes Agent、OpenClaw、Muse）或讲者本人担任指挥官，掌握本手册、地基（01～08）和 `06-产品方法论`，据此给本地 agent 写五段式指令（Context / Request / Output format / 红线禁止 / Checkpoint）并验收。任务需要的背景和要读的文件路径，由指挥官从地基里挑出来写进 Context。
>
> **本地 agent**（Codex、WorkBuddy、Antigravity、AI IDE 等）以指挥官的五段式指令为准：只读指令里点名的文件，不自己去翻项目背景；指令和本手册冲突时，停下汇报，不要自己选。
>
> 人负责四件事：①定做什么（模块、范围）；②定业务规则；③裁【待确认】；④最终验收（通过或打回）。

## 一、项目说明

- 项目名：顺诚进销存（SC-JXC）。SC = 顺诚，JXC = 进销存
- 公司：顺诚商贸（杭州）有限公司，一家小型快消品批发商（虚构公司，教学用）
- 目标：用一套轻量进销存系统，替代现在的"微信接单 + Excel 记账 + 纸质单据"
- 一期范围：基础资料、采购、销售、库存四个模块（详见 `01-全局背景信息/30-系统模块与边界.md`）
- 文档读者：产品、开发、测试、业务负责人。全中文；给评审人看的文档不出现英文技术词

## 三、权威来源排序（打架时听谁的）

0. **拍板记录**（`03-产品设计/<模块>/<单据>/<单据>-拍板记录.md`）：人已经拍板的结论，优先于需求调研里的待确认问题
1. **字段清单详细稿 TSV**：字段叫什么、什么类型、必不必填、从哪来，只认它（初稿只是过程稿）
2. **业务主PRD**：状态、动作、谁能做、业务规则，只认它
3. **Demo PRD**：页面怎么摆、怎么点、什么时候提示，只认它
4. **原型标注**：解释原型上每个角标，只能引用上面几项

`08-相关资料`（竞品调研、接手项目的历史资料）只作参考，排在上面全部项目文件之后，也低于 01、02；引用时注明出处；和项目文件冲突时，列出来标【待确认】，不要自己选。

下游只能引用上游，不能反过来改上游。原型上多了一个按钮，不代表业务上就该有这个动作。全局规则（01）和单据文件冲突时，先列为【待确认】，不要自己选。

## 四、文件命名

- 单据目录：`03-产品设计/<模块>/<单据>/`，例如 `03-产品设计/采购管理/采购订单/`
- 规则层文件用"-"：`采购订单-主PRD.md`、`采购订单-字段清单-详细稿.tsv`
- 页面层文件用"_Demo_"：`采购订单_Demo_列表页.md`
- 原型页面：`99-产品原型/前端工程/src/views/<模块>/<单据>/列表页|新增编辑页|详情页/index.vue`；标注：`99-产品原型/标注/<单据><页面>-标注.md`
- 角标编号：列表页 L1、L2…；新增编辑页 F1、F2…；详情页 D1、D2…
- 不确定的内容统一写【待确认】，并说明缺什么信息

## 五、AI 协作红线

1. 只在任务指定的目录里新建文件；任务没点名的已有文件一律只读
2. 不新增字段清单里没有的字段，不新增主PRD 里没有的规则，不发明第二套状态
3. 信息不足、前后矛盾时，写【待确认】并列出来，不自己猜着补
4. 先盘点依赖再动手：上游文件缺了或没确认，先汇报，不硬做
5. 一次只做一层产物（字段、规则、页面、原型分开做）
6. 每个 md 产出文件开头写明"产出步骤"（对应 05-提示词合集 的哪个文件）和"依据"（读了哪些文件）；TSV 文件只放表格，产出步骤见 `05-提示词合集/00-执行顺序.md`
7. 完成后汇报：新建了哪些文件、各有多少条目、还有哪些【待确认】
8. 禁止 git commit 或 push；禁止删除、移动、重命名任何已有文件
9. 不联网查资料、不连接任何真实系统；前端工程只允许按现有 `package-lock.json` 执行 `npm install`，不新增、不升级依赖
10. 需求变化时，按 `06-产品方法论` 的"改动入口表"找到该改哪一层，从上游改到下游

## 六、新任务开工前先读（按顺序）

1. 本文件
2. `01-全局背景信息/00-背景信息索引.md`，再按需读 01 下其他文件
3. 当前单据的拍板记录（如果有）
4. 当前模块对应的 `02-需求调研` 文件
5. `04-常用模版` 里对应的模版
6. 上一步已经确认的产出文件
7. （可选）`08-相关资料` 各子目录的 `说明.md`，任务需要时再按需取用

## 七、原型工程约定（摘要，完整版见 `07-UI规范库/前端技术约定.md`）

- 技术栈固定：Vue 3 + Element Plus（中文）+ Vue Router（hash 模式）+ Pinia + Dexie（IndexedDB），Vite 打包成单个 `dist/index.html`，双击能开
- 只有前端，没有后端和服务器：演示数据存在浏览器本地数据库，第一次打开写入种子数据，刷新不丢，顶部"重置演示数据"恢复初始
- 页面不直接碰数据库：`views/` 只能通过 `src/mock/repos/<单据>.js` 读写；种子数据 `src/mock/seed/<单据>.js` 只能抄该单据的"演示数据.md"
- 每个单据一个文件夹 `src/views/<模块>/<单据>/`：`routes.js`、`anno.js`、`rules.js`、`service.js` + 列表页 / 新增编辑页 / 详情页
- 先复用公共组件：查询区 `QueryBar`、状态标签 `StatusTag`、原因弹窗 `ReasonDialog`、底部按钮栏 `FooterBar`、角标 `v-anno`
- 原型红线：字段只来自字段清单详细稿，规则只来自主PRD 和 Demo PRD；不加依赖、不改打包配置、不做登录、不连后端
- 运行：`npm install` → `npm run dev`（边改边看）→ `npm run build`（生成 dist）
