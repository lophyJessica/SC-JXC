# 用例数据推演模板

> **用途**：拿真实/演示数据把一张单**从头演到底**，验证「数据撑不撑得起」——字段装不装得下、规则什么时候触发、页面放不放得下。
>
> **前置**：主PRD（规则）已确认、演示数据/字段清单已就绪。
>
> **职责**：业务规则落地后的**数据验算**。不得新增状态、字段或规则；算不通时回上游改完再跑。

## 一、推演内容

拿数据把一条单从草稿走到关闭，每步记录四件事：

| 步骤 | 状态 | 关键数据（供应商/商品/数量/单价/金额） | 触发/卡住的规则与校验 | 存疑点 |
| --- | --- | --- | --- | --- |
| 1 新建 | 草稿 | 杭州优果 / 原味薯片 / 500 / 12.9 / 6450 | 停用资料不可选：筛选出所有启用 | — |
| 2 提交 | 待审核 | 金额 15620 | 达 2 万审批线，需升级审核 | 要不要测一组正好 2 万的边界 |
| 3 确认入库(部分) | 部分完成 | 到货 300/500 | 未入库 200 > 0 → 部分完成 | 部分完成还能驳回吗 |
| 4 剩余收完 | 已完成 | 补 200 | 未入库=0 → 已完成 | — |
| … | | | | |

## 二、每个必考点必须单独走一条

| 必考点 | 用哪组数据验 | 预期触发 |
| --- | --- | --- |
| 2 万审批线 | 金额 20000 边界 | 升级审核 |
| 停用资料不可选 | 已停用供应商/商品 | 不能选、或灰化 |
| 进价涨价提醒 | 商品成本 vs 本次进价 | 弹提醒 |
| 部分完成只能关闭 | 部分完成状态 | 有"关闭"无"作废/退回" |

## 三、喂给 AI 的提示词（可直接抄）

```text
Context: 演示数据在 03-产品设计/采购管理/采购订单/采购订单-演示数据.md(杭州优果/原味薯片等)
Request:
1. 用演示数据造一条完整采购订单，从草稿走到关闭
2. 每步输出: 状态 | 关键数据(供应商/商品/数量/单价/金额) | 触发或卡住的规则/校验
3. 重点验: 2万审批线、停用资料不可选、进价涨价提醒、部分完成只能关闭
4. 标出"数据撑不住/规则触发时机存疑"的点
红线: 不伪造数据; 存疑写进待确认
Checkpoint: 走完给我结论
```

> 状态机推演验「状态走得通」，用例数据推演验「数据撑得起」——两者都是前端编码前的强制关卡，任一没过就回上游补规则。
